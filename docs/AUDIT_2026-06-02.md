# SwiftFloris — Deep engineering audit (2026-06-02)

Third aggressive correctness / security / reliability / UX pass over the whole
tree (`:app` + `:lib:*`), building directly on the deferred backlog from
[`AUDIT_2026-05-29.md`](AUDIT_2026-05-29.md). Method: a 25-agent finder workflow
re-verified every deferred item against live source and hunted 10 subsystems for
new issues; each candidate was put through an independent adversarial
verification pass (confirm against the real code, or refute). Only
high-confidence, behavior-preserving fixes were applied; everything that needed
a device, fixtures, or a structural change was left on the deferred list with a
note instead of being fixed blind.

> **Build/verification caveat.** This host has **no Android SDK** (`ANDROID_HOME`
> empty, `local.properties` `sdk.dir` is a placeholder), so the gradle build
> gates **could not be run here**. Every change was verified by static reasoning
> + re-reading the live code + dangling-symbol greps after each rename/removal.
> **Before release, run on an SDK host:**
> `./gradlew :app:verifyNoInternetPermission :app:testDebugUnitTest :app:lintDebug :app:assembleDebug`
> No hard invariant (no-INTERNET, Apache-2.0, encrypted-dict, FLAG_SECURE) was
> loosened, no new dependency was added, and no new user-facing string resource
> was added (Crowdin-safe — the one new dialog reuses existing strings).

## 1. Deferred backlog from 2026-05-29 — resolved

The prior pass left ~25 vetted-but-deferred findings. This pass closed them as
follows (applied = code changed and reviewed; clean = re-verified as already
guarded / false positive; still-deferred = genuinely needs a device).

### Applied (verified, behavior-preserving)

| # | File | Fix |
|---|------|-----|
| Bidi reorder | `ime/bidi/VisualLogicalReorderer.kt` | `logicalToVisual` now delegates run ordering to `Bidi.reorderVisually` (the stdlib UAX#9 **L2** implementation) instead of an ascending-level `sortedWith`, and every RTL run is reversed by **code point** (`reverseByCodePoint`) instead of `String.reversed()`, so supplementary-plane characters keep their surrogate pairs and combining marks stay attached. |
| Clipboard media query | `ime/clipboard/provider/ClipboardMediaProvider.kt` + `ClipboardDatabase.kt` | `query()` now **returns** the orientation cursor instead of discarding it and falling through to the full row; the DAO `SELECT (:projection)` (which bound a column *name* as a *value*, always returning the literal string `"orientation"`) was replaced by `getOrientationCursorById` selecting the real `\`orientation\`` column. |
| Importer entry cap | `ime/dictionary/DictionaryImporter.kt` | `parseZip` now calls `checkEntryLimit(found.size)` against the **cumulative** archive total after each entry, closing the per-file-only cap bypass (256 × 49 999 ≈ 12.8 M entries). |
| Voice buffer desync | `ime/voice/VoiceCommandExecutor.kt` + `StreamingVoiceTranscriptBuffer.kt` | `removeItemFromList` snapshots the committed segments before the in-place mutation and `restoreCommittedSegments(...)` rolls them back on all three editor-edit failure exits, ending the silent buffer/editor desync. |
| Subtype switch fallback | `ime/core/SubtypeManager.kt` | `switchToNext/PrevSubtype` rewritten with index-based wrap; a missing active subtype falls back to the first/last real subtype instead of the non-selectable sentinel `Subtype.DEFAULT`, and an empty list is a no-op. |
| Clipboard close leak | `ime/clipboard/ClipboardManager.kt` | `close()` now cancels the whole `ioScope` (not just `cleanUpJob`), releasing the long-lived history flow collector launched in `initializeForContext`. |
| Clipboard file id | `ime/clipboard/provider/ClipboardFileStorage.kt` | `cloneUri` no longer uses boot-relative `System.nanoTime()` as the file id (which can collide with pre-reboot ids and silently overwrite a stored clip); it draws from an `AtomicLong` and skips any id already on disk. |
| n-gram concurrency | `ime/dictionary/PersonalBigramStore.kt` + `PersonalTrigramStore.kt` | `tablesByLocale`/`lastSeenByLocale` are now `ConcurrentHashMap` (mixed `loadGuard` vs `synchronized(tablesByLocale)` lock regimes could corrupt a plain `HashMap`), and the cross-locale `pendingCommits` counter is an `AtomicInteger`. |

| Translation whitespace | `ime/translate/TranslationRouter.kt` (+ test) | inter-sentence whitespace is split off each piece, the core is translated, and the original separator is re-appended verbatim (Bergamot doesn't echo trailing whitespace). |
| Inline-autofill latch leak | `ime/nlp/NlpInlineAutofill.kt` | (covered by the onDestroy clear below + prior `withLock` fix). |
| Resources rebuild | `FlorisImeService.kt` | `distinctUntilChanged()` before the locale-pair `collectIn`, so duplicate emissions no longer rebuild `resourcesContext`. |
| Crash-handler IO | `lib/crashutility/CrashUtility.kt` | `readFile` (run inside `uncaughtException`) is wrapped so an IOException can't crash the crash handler and skip the notification/dedup logic. |
| Addon asset traversal | `ime/addon/DictionaryPackDescriptor.kt` | `fldicAssetPath`/`zipfAssetPath` now reject `..` path segments (in addition to absolute paths). |
| MCP byte cap | `ime/mcp/AndroidMcpClient.kt` | the daemon-response cap now compares the **UTF-8 byte length** to `MAX_PAYLOAD_BYTES` (UTF-16 char count is only a lower bound, so an oversized multibyte response slipped through), mirroring the request side. |

### Re-verified clean (no change — already correct)

- **`ZipUtils.isUnsafeEntryName` "missing NUL check"** — for the **third** time a
  finder reported this as missing. It is **present**: `cat -A` shows
  `name.contains('^@')` where `^@` is a raw NUL byte. The proposed "fix"
  `name.contains(' ')` (literal space) would wrongly reject every filename
  containing a space. Applied the long-pending cosmetic instead: the raw NUL byte
  is now the readable `'\u0000'` escape so it stops fooling auditors. **No
  behavior change.**

## 2. New findings this pass — 28 confirmed by adversarial verification

**Applied (20):**

### Security
- **[high] Sensitive media cloned to unencrypted disk** — `ClipboardManager.onPrimaryClipChanged`.
  `fromClipData(cloneUri = true)` wrote IMAGE/VIDEO bytes + a DAO row to disk
  *before* the `if (!item.isSensitive)` history gate, so a clip a password
  manager marked `EXTRA_IS_SENSITIVE` left a plaintext file on disk that nothing
  deleted until the next reconcile. Sensitivity is now decided before cloning
  (`cloneUri = !isSensitiveClip`) so the bytes are never written.
- **[high] Addon signing-pin bypass** — `SigningFingerprint.readSignatures`.
  Multi-signer APKs are now refused (`hasMultipleSigners()` → null) instead of
  pinning an ambiguous `apkContentsSigners.first()`; the `signingCertificateHistory`
  (oldest/rotated-away cert) fallback was dropped; and the API 26/27
  `GET_SIGNATURES` path requires exactly one signature.
- **[medium] FLAG_SECURE missing in incognito** — `FlorisImeService.applyFlagSecureForCurrentField`
  now also sets `FLAG_SECURE` when `activeState.isIncognitoMode`, matching every
  other sensitive-data gate. v1.8.231 adds the mid-session smartbar-toggle
  callback, so the active IME window re-applies the same policy immediately.
- **[low] Decrypted-dictionary plaintext slice un-scrubbed** — `UserDictionaryScreen`
  encrypted import now wipes the 1 KiB `sniff` buffer in the same `finally` as the
  full plaintext.

### Concurrency / resource leaks
- **[medium] `ClipboardMediaProvider.cachedFileInfos` data race** → `ConcurrentHashMap`.
- **[medium] Inline-autofill view leak across rebind** — `FlorisImeService.onDestroy`
  now clears `NlpInlineAutofill` (its StateFlow held `InlineContentView`s built
  against the dead service Context; `onFinishInput` is not guaranteed before
  `onDestroy`).
- **[low] SAF persisted-URI-permission leak** — `SyncSettingsScreen` releases the
  previous folder / manual-export grant before taking the new one.
- **[low] Backup/Restore workspace not closed on system-back/nav-up** — both
  screens got a `DisposableEffect { onDispose { ... } }` guard so extracted
  clipboard plaintext / decrypted prefs don't linger in cache.
- **[low] KMP package OOM** — `KeymanPackageParser` gained an entry-count cap
  (`MaxEntries`) and a cumulative-LDML-bytes budget (`MaxTotalLdmlBytes`).

### Correctness
- **[low] `Gesture.hashCode` inconsistent with `equals`** — hashed the full
  500-element backing arrays incl. stale tail, silently breaking the glide
  suggestion cache; now hashes only the active `[0, size)` prefix.
- **[medium] `SnyggCutCornerDpShapeValue` dropped fractional dp** — `getInt`→`getFloat`,
  so `cut-corner(4.5dp,…)` round-trips (regression test added).
- **[low] `SnyggTextMaxLinesValue` overflow** — `toInt()`→`toIntOrNull() ?: NoneValue`.
- **[medium] KLC metadata mis-extraction** — `substringAfter(uppercasedToken)`
  returned the whole line for lowercase headers; now `substring(token.length)`.
- **[low] Voice IME switch silent no-op** — pre-API28 null-token path now shows
  the IME picker instead of returning a silent `false`.
- **[low] `DictionaryPackDescriptor` locale mismatch** — language invariant now
  uses `lowercase(Locale.ROOT)` to match the catalog (Turkish-I safety).
- **[low] `PersonalDictionaryImportBatch` undo over-delete** — inserted ids are
  now key-matched against `(word, locale)` keys this batch actually inserted, so
  Undo can't delete a word the user auto-learned concurrently during the import.

### UX / maintainability
- **[low] MCP per-tool switch showed OFF while daemon muted** — switch now shows
  the true persisted per-tool state; only interactivity is gated on the daemon.
- **[low] Destructive "Reset all learning" had no confirmation** — now gated
  behind a `JetPrefAlertDialog` (reuses existing strings; the per-category resets
  stay unguarded, the personal dictionary is untouched).
- **[low] Dead `disabledToolSet` state + unused `CheckCircle` import** removed.

**Applied on a second pass (originally deferred):**

- **#3 [medium] glide-classifier shared `Gesture` state race** —
  `StatisticalGlideTypingClassifier` now serializes all `gesture` access behind a
  `gestureLock`: `addGesturePoint`/`clear` mutate under the lock, and
  `getSuggestions` takes a single clone-under-lock snapshot that the lookup,
  classification, and cache-put all share. Provably behavior-preserving (the
  snapshot is the same gesture state, minus the torn read), so the finder's
  `needsDevice` flag — which was about end-to-end *validation*, not fix
  correctness — does not block it. Heavy classification stays outside the lock.

**Reconsidered — NOT a bug (left unchanged):**

- **#15 `AddonEnumerator.bundleSizeBytes = 0L`** — on close reading this is a
  *documented deliberate trade-off*, not a defect. The in-code comment
  (`AddonEnumerator.kt:155-164`) records that the prior `File(sourceDir).length()`
  measurement was removed precisely because the APK file size is the wrong metric
  (the IME never loads the APK into RAM) and it false-rejected legitimate 64MB+
  packs; real enforcement is intentionally deferred to asset-mounting (Next-10.4).
  The agent's proposed fix would re-introduce that exact regression. The only
  residual is a cosmetic "0 B" in a detail view — not worth overriding a
  documented decision blind.

**Still deferred — `fixIsSafe=false`, genuinely need a device / structural change:**

- **#6 `StickerMediaProvider.openFile`** confused-deputy hardening — the provider
  is already `exported=false` (no current exploit); a SAF tree-vs-document grant
  allow-list needs device validation and a wrong check silently breaks legitimate
  imported stickers.
- **#12 Restore `copyTo(overwrite=false)`** id-collision → wrong restored media
  content; needs an id-remap threaded through restore + a Room fixture.
- **#19 / #20 LDML multi-codepoint** (cluster output truncated to first codepoint;
  `\u{...}` space-separated lists rejected) — both require widening
  `HardwareKeyEntry` to carry a `String` output.
- **#21 KLC dead-key glyph emitted immediately** — correct fix is wiring the
  dead-key composition pass in the runtime mapper, not nulling the printable slot.

## 2b. Second-wave audit — previously-uncovered subsystems

A 12-agent follow-up workflow hunted the 6 subsystems the first pass never
touched (emoji, CJK input, smart-compose, media/sticker, the Latin NLP decoder
core, keyboard rendering), each finding adversarially verified. 21 confirmed;
**15 applied, 6 deferred.**

**Applied:**

- **[high] SymSpell distance-1 auto-commit over-aggression** —
  `LatinLanguageProvider.knownEdits1` returned shared-delete candidates labelled
  distance 1 with NO verification, so a true-distance-2 typo could auto-commit
  (mutate text) at the looser 0.78 threshold. Now verifies actual Damerau
  distance per candidate, exactly like `knownEdits2`.
- **[high] Smart-compose ghost text bypassed `SensitiveFieldGuard`** —
  `NlpManager.buildGhostTextCandidate` called the provider directly, so on an
  `IME_FLAG_NO_PERSONALIZED_LEARNING` field the keyboard surfaced ghost text from
  the user's personal n-grams. Now gated through `SensitiveFieldGuard.isSensitive`
  on the active editor's `inputType`/`imeOptions`.
- **[medium] Composer crash on empty rules** — `WithRules.toRead` used `maxOf`
  (throws on an empty deserialized `rules` map → crashes text entry); now
  `maxOfOrNull ?: 0`, matching the sibling transliterators.
- **[medium] Emoji pin cap bypass** — `pinEmoji`/`unpin`/`move`/`remove` wrote via
  uncapped `build()`, so a later unrelated emoji tap silently truncated the
  oldest user pins; all four now route through a capped `setCapped` setter.
- **[medium] Emoji history unclearable after disable** — `deleteHistory`/
  `deletePinned` early-returned when history was off, stranding a typed-emoji log
  with no erase path; guard removed (clearing is always safe) and the reset
  buttons un-gated.
- **[medium] Overlay correction used plain Levenshtein** while SCOWL used Damerau,
  so a transposition typo of a learned word was misranked; unified on
  `boundedDamerauLevenshteinDistance` (removed the now-unused `boundedLevenshtein`).
- **[medium] Sticker folder SAF grant leak** — `MediaScreen` now releases the
  prior persisted grant on re-pick and on clear (mirrors the sync screen).
- **[low] EmojiData parser** — a blank-value base line now drops its whole set
  (`skipVariations`) instead of letting orphaned tab-indented variations reseed a
  bogus standalone emoji.
- **[low] `removeSuggestion` constant-true** (`removedFromUserDict || true`) →
  returns the real result.
- **[low] Next-word bootstrap confidence** — `0.001 * frequencyFor` (a mis-ported
  ×255 multiplier) collapsed every bootstrap word to ~0.300; respread to a real
  `0.18 + 0.06 * f` band.
- **[low] `SmartComposeResultFilter` stale tokenCount** after whitespace
  normalization — recomputed.
- **[low] `RewriteRouter` accessOrder LRU** unsynchronized — guarded with a lock
  (latent: only wired in tests today, but the hazard is real once dispatched).
- **[medium] Heuristic smart-compose ignored `composingPrefix`** — the in-progress
  word was treated as a finished preceding token; now stripped before n-gram
  context extraction.
- **[low] Sticker `query()` placeholder render** — no longer renders/writes a
  throwaway 512×512 PNG (whose size `openFile` never serves) for user stickers.
- **[low] `CustomEmojiTagStore` non-atomic rename fallback** — on `renameTo`
  failure it hand-copied into the live file (could truncate on a mid-write
  throw); now keeps the previous file intact.

**Deferred (verified real, but `fixIsSafe=false` / needs a device):**

- **CJK Han `code ASC` candidate ordering** (auto-commits an arbitrary
  low-frequency word) and the **unescaped SQL `LIKE` prefix** from a
  pack-controlled key-code alphabet — both want a device + Han DB fixture.
- **`NlpInlineAutofill` inflated-view leak** on the timeout/stale-seqId paths —
  needs an emulator with an inline-autofill provider to validate the release.
- **Honeycomb geometry cluster** (`HoneycombKeyCell.contains` flat-top vs the
  pointy-top grid → ~42% dead-zone gaps; `isPointInFlatTopHex` edge test;
  flat-top docstrings). The math is statically verified, but it's an opt-in
  non-default layout and the fix must change hit-test + `HoneycombHexShape` Path
  + docs **in tandem** with on-device visual confirmation — deferred as one
  coherent device-validated change rather than a blind Path rewrite.
